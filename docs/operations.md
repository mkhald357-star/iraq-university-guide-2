# دليل التشغيل والطوارئ — منصة (iraqmajors.com)

> يُراجَع كل 3 أشهر.

## 1) كيف يُنشر الموقع

| البند | القيمة |
|---|---|
| الاستضافة | Cloudflare Pages (مجانية؛ موقع ثابت بلا خادم ولا قاعدة بيانات) |
| المستودع | `github.com/mkhald357-star/iraq-university-guide` |
| فرع الإنتاج | `master` |
| أمر البناء | `npm run build` |
| مجلد الإخراج | `out` |
| إصدار Node | 20 (ملف `.nvmrc`) |
| متغيرات البيئة | **لا شيء**. الموقع لا يحتاج أي سر. إن طلب أحد إضافة مفتاح فهذا تغيير يمر أولاً بإعادة تقييم أمنية |

ما يحدث في كل بناء (`postbuild` ← `scripts/security/postbuild.mjs`):
- يُفشل النشر إن وُجدت خرائط مصدر، أو سكربت من أصل خارجي، أو قيمة نائبة، أو ملف حساس (`.env`، مفاتيح، PDF).
- يولّد `out/_headers`: ترويسات الأمان العامة + CSP لكل صفحة بهاشات سكربتاتها.
- يولّد `out/integrity.json` و`out/version.json` (الـcommit المنشور) لمراقبة السلامة.

**لا نشر يدوي أبداً** (لا رفع ملفات من لوحة Cloudflare، ولا `wrangler deploy` من جهاز). الطريق الوحيد: commit على `master` ← CI يمر ← Cloudflare يبني. فحص السلامة اليومي يُنذر بأي ملف لم يأتِ من المستودع.

## 2) المراقبة (`.github/workflows/monitor.yml`)

| الفحص | التوقيت | يُنذر عند |
|---|---|---|
| `headers` | كل 3 ساعات | الموقع لا يعمل، أو ترويسة أمان مفقودة، أو سكربت خارجي ظهر، أو `security.txt` ينتهي خلال 30 يوماً |
| `integrity` | يومياً 03:47 UTC | أي ملف حي يختلف عن إعادة بناء الـcommit المنشور، أو الـcommit المنشور ليس من تاريخ `master` |

الإنذار: بريد GitHub التلقائي لمالك المستودع عند فشل أي تشغيل (تأكد من تفعيل «Actions → Send notifications for failed workflows» في إعدادات إشعارات حسابك).
تشغيل يدوي: GitHub ← Actions ← Monitor live site ← Run workflow. أو محلياً: `node scripts/security/check-live.mjs headers`.

> ملاحظة: فحص `integrity` يفشل حتى يُنشر أول commit يحتوي هذا النظام (لا `version.json` قبل ذلك). هذا متوقَّع.

## 3) الطوارئ

### أ) الموقع يعرض محتوى لم نكتبه (تشويه/حقن) أو فشل `integrity`
1. **لا تحذف شيئاً** قبل التوثيق: لقطة شاشة + `curl -s https://iraqmajors.com/<الملف> > evidence.html` + سجل تشغيل الفحص.
2. Cloudflare ← Workers & Pages ← المشروع ← Deployments: اختر آخر نشر سليم ← **Rollback to this deployment** (فوري).
3. غيّر كلمة مرور Cloudflare وGitHub، وأبطل كل جلسة نشطة وكل API Token في الحسابين، وراجع سجل التدقيق (Cloudflare: Manage Account ← Audit Log؛ GitHub: Settings ← Security log).
4. افحص المستودع: `git log --all --since="7 days ago"` وأي commit أو إجراء لا تعرفه. افحص `.github/workflows` بالذات.
5. أعد النشر من commit تثق به، وشغّل `monitor` يدوياً حتى ينجح.
6. اكتب ما حدث في §6 أدناه.

### ب) الموقع متوقف
1. هل المشكلة عندنا؟ <https://www.cloudflarestatus.com>.
2. آخر نشر فشل؟ Deployments ← سجل البناء. إن كان `postbuild` هو الذي أفشله فهو يقول السبب صراحة (خريطة مصدر، سكربت خارجي…): **أصلح السبب، لا تُعطّل الفحص**.
3. الحل الفوري: Rollback لآخر نشر ناجح.

### ج) صفحة تعطّلت بعد تحديث (CSP يمنع سكربتاً)
- العَرَض: الصفحة تظهر بلا تفاعل، وفي Console: `Refused to execute inline script`.
- السبب الوحيد الممكن: سكربت مضمَّن جديد لم يُحسب هاشه. أعد البناء (الهاشات تُحسب من الملفات الفعلية تلقائياً). إن استمر: Rollback ثم افحص محلياً.
- **ممنوع** إضافة `'unsafe-inline'` إلى `script-src`. حل طارئ مؤقت مقبول: `CSP_REPORT_ONLY=1` كمتغير بيئة في Cloudflare (يحوّل السياسة إلى مراقبة فقط) ثم إزالته بعد الإصلاح.

### د) سرّ تسرّب (رغم أن الموقع لا يحتاج أسراراً)
1. أبطله فوراً من مصدره (GitHub token، Cloudflare token…).
2. وجوده في تاريخ git يعني أنه مكشوف للأبد: الإبطال هو الحل، لا إعادة كتابة التاريخ.
3. `gitleaks` في CI يفحص كل التاريخ في كل push.

### هـ) بلاغ ثغرة من شخص خارجي
القناتان الوحيدتان: تلغرام @kaxfk وإنستغرام ka_xf (منشورتان في `/.well-known/security.txt` و`/privacy`).
- ردّ خلال 72 ساعة بالاستلام. لا تطلب من المُبلِّغ تجربة إضافية على الموقع الحي.
- أصلح ← انشر ← أبلغه ← وثّق في §6.

### و) صفحة صيانة
لا حاجة لنظام منفصل: انشر commit يستبدل `app/page.tsx` برسالة صيانة، أو Rollback لنشر قديم سليم. (موقع ثابت: لا بيانات تتلف أثناء التوقف.)

## 7) قائمة تحقق الإعدادات الخارجية (للمشغّل)

بنود لا يملكها الكود وتؤثر في الأمان:

**GitHub:** مصادقة ثنائية، وDependabot alerts وsecurity updates، وإجراءات GitHub فقط مثبَّتة بـSHA، وصلاحيات سير العمل للقراءة فقط.

**الاستضافة (Cloudflare Pages):** مشروع Pages بأمر البناء `npm run build` (ليُنفَّذ `postbuild` فتُولَّد ترويسات الأمان وملفات السلامة)، ومجلد الإخراج `out`، وتعطيل معاينات الفروع غير الإنتاجية، وSSL/TLS على Full (strict) وAlways Use HTTPS وأدنى TLS 1.2، وتعطيل كل ميزة تحقن سكربتات في الصفحة (Rocket Loader، Email Obfuscation، Web Analytics التلقائي، Zaraz) لأن CSP بالهاشات ستمنعها.

**النطاق:** DNSSEC، وسجل CAA، وسجلات SPF/DMARC/DKIM تمنع انتحال البريد (النطاق لا يرسل بريداً)، وقفل نقل النطاق وتجديد تلقائي، ومصادقة ثنائية عند المسجِّل.

**تحقق آلي من البنود المرئية من الخارج** (يُشغَّل بعد أي تغيير في إعدادات النطاق):

```
node scripts/security/check-owner-checklist.mjs
```

يفحص الخوادم الاسمية وCAA وSPF وDMARC وDKIM وDNSSEC وتحويل HTTP وإصدارات TLS، ويعيد رمز خروج 1 ما دام بند مفتوح.

**تثبيت آلي للإعدادات** (معاينة افتراضياً ولا يكتب إلا مع `--apply`، ولا يعدّل سجلاً موجوداً بقيمة مختلفة):

```
CLOUDFLARE_API_TOKEN=<رمز مقيَّد> node scripts/security/apply-cloudflare.mjs [--apply] [--skip=ssl,dnssec]
GITHUB_TOKEN=<رمز مقيَّد>         node scripts/security/apply-github.mjs     [--apply]
```

الرموز تُمرَّر عبر متغيرات البيئة فقط ولا تُحفَظ ولا تُطبَع، وتُحذَف من لوحة المزوِّد بعد الاستعمال.
